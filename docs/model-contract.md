# Model contract

The PyTorch model, the numpy reference simulator and `web/model.js` must agree exactly. This file is the spec all three are written against; `web/tests/fixtures/parity_v1.json` is the executable check (browser vs Python, currently agreeing to ~2e-14 on logits).

## Signs and weights
- Sign per neuron from `consensus_nt` (full lowercase names in the raw data): acetylcholine +1; gaba, glutamate, histamine −1; dopamine, octopamine, serotonin, unclear or missing 0 (no output). **Signs are never trained.**
- Base weight `W0[post, pre] = sign(pre) · synapses / total_input_synapses(post)`, where the denominator is the post neuron's whole-connectome input, not just the input inside the extracted circuit.
- Folded weight used everywhere downstream:
  `W[post, pre] = exp(log_gain + post_scale[type(post)]) · W0 · exp(pre_scale[type(pre)])`.
  Trainable gains are per cell type and diagonal, so the sparse `W0` never changes and backprop needs only `W0ᵀ`.

## Frame order (identical in torch, numpy and JS)
1. Frame `f` has time `t = f / fps`.
2. Compute the stimulus drive for that time; `u[input_idx] = input_gain[input_kind] · drive`.
3. Run `substeps` synchronous updates `r ← (1−α)·r + α·clip(W·r + bias + u, 0, r_max)`, where every `W·r` uses the value of `r` from before the substep.
4. `logits = W_out · r[dn_idx] + b_out`.

`α = dt_sub·1000 / τ_ms` per neuron. Constants (fps, substeps, r_max, warm-up, stimulus parameters, input noise) live in `flybrain/config.py` and are written into the bundle manifest; JS reads them from the manifest and hardcodes none.

## Decision rule
An action fires when the same non-"none" class stays above `decision.p` for `decision.frames` consecutive frames. `flybrain/train.decide` and `web/decision.js` implement the same rule and must stay equivalent.

## Bundle
- `web/assets/circuit_v1/manifest.json` describes every `.bin`: fields concatenated in order, little-endian, each field aligned to its item size, sha256 per file.
- `csr.bin` values already include the gain and the trained scales, so the browser does no parameter maths.
- The parity fixture is generated by `flybrain/sim_numpy.py` **from the exported bins**, never from torch state.
- World coordinates (µm): `world = M·(nm − centre)/1000` with `M = [[−1,0,0],[0,0,−1],[0,−1,0]]` (det +1): the fly's left is at −X and the brain is up (+Y).
- `manifest.viz.role_ref` gives a display scale per role so the browser can show activity as change from rest.

Regenerate the bundle and fixture with `uv run python -m flybrain.export [--checkpoint …]`.

## Data-access rules (the raw dataset is 31 GB; development machine had 30 GB of RAM)
- Read feathers with pyarrow column projection; filter (e.g. `weight >= 5`) before converting to numpy or pandas.
- Use the `*-traced-only` weights and syn-partners files. Never load `syn-points-*` or the full `syn-partners`.
- Neurons are `body-annotations` rows with `superclass` not null and `status == "Traced"`.

## Reporting rules
- Report results only from `results/summary.json`.
- Claim "real wiring beats X" only when the mean gap exceeds 2 pooled standard deviations across seeds (`flybrain/evaluate.pooled_gap_claim`).
